## Particular questions for this revision

1. Is the early desktop compatibility checkpoint feasible with the pinned SDK APIs and actual applications? Fallback must fail the checkpoint. An unavailable client/configuration path must produce evidence and a resolution request, not silent substitution.
2. Are the plain wire DTOs, runtime-specific serializers, ISO-8601 private timestamps, complete embedded report and independent Python assertions consistent across net48/net10? Does the SDK result retain false/null fields and existing report casing?
3. Does the eight-slot/five-second accept timer interact correctly with the 30-second end-to-end budget, disconnect cancellation, bounded queue, every Raise status and Idling re-arm? Do tests cover arrivals at the last drain and late completion?
4. Do document-lifetime checks, atomic sidecar snapshots, installer ownership and rollback preserve existing sample/command/export behavior? Are promised real-host checks distinguishable from source guards and simulated tests?
5. Are the nine task boundaries independently testable and proportionate? The plan recommends Native execution but leaves selection to the author; external R2/R3 remain explicit regardless of method.
