Reviewer: Codex, in this separate review context; I did not author the spec. Reviewed revision 1 at `b56c0dc219e1269f5b90542004267a2d388f338d`, dated October 20, 2026.

1. **R1-01 — Major: define the client/protocol combination that satisfies A8.**
   [A8 (line 143)](../../specs/2026-10-20-revit-mcp-bridge-design.md) requires the “intended seminar agent client,” but does not identify it or decide whether older-protocol fallback satisfies acceptance. A2 explicitly requires `2026-07-28`.

   **Failure scenario:** the SDK harness passes using `2026-07-28`, while the seminar application succeeds only through an older revision. The evidence would be accurately recorded, but reviewers could disagree about whether the author’s requirement was met.

   **Smallest correction:** name the intended client application(s), establish a version/configuration baseline, and explicitly state whether fallback is acceptable for A8.

   **Verification:** capture discovery, context acquisition, a readiness call, and a structured failure through each required application, recording the actual protocol used.
2. **R1-02 — Major: require an incomplete-coverage result through the full MCP pipeline.**
   [Section 5 (line 76)](../../specs/2026-10-20-revit-mcp-bridge-design.md) correctly distinguishes incomplete coverage from a readiness pass. However, [A5–A6 (line 140)](../../specs/2026-10-20-revit-mcp-bridge-design.md) do not explicitly require this outcome. All three principal samples have complete coverage, and the [existing comparator (line 50)](../../../../projects/revit-readiness/tests/verify_information_evidence.py) requires it.

   **Failure scenario:** a valid checklist lacks a requirement for a used type. The evaluator can produce zero missing-value findings while reporting unexamined elements. An adapter that drops those elements or mishandles false completeness flags could pass the three principal comparisons.

   **Smallest correction:** add temporary negative controls for an unresolved declared element and a used type without a matching requirement. Prepare these before acquiring a fresh context so the test reaches evaluation instead of stopping at `ContextChanged`.

   **Verification:** assert a successful tool execution containing incomplete coverage, exact unexamined identities/reasons, and preserved false flags. Confirm the client does not present zero findings as a readiness pass. Keep the three existing sample expectations unchanged.
3. **R1-03 — Minor: specify the timeout before a complete pipe request exists.**
   [Section 6 (line 105)](../../specs/2026-10-20-revit-mcp-bridge-design.md) requires bounded reads and deadline-derived timers, but does not specify when the timer starts for an accepted connection that has not supplied a complete header/body.

   **Failure scenario:** eight stalled connections occupy every connection slot before a request deadline can be parsed. The general bounded-read requirement leaves the recovery interval unspecified.

   **Smallest correction:** define an accept-time frame-receive limit, then cap subsequent processing by the validated remaining request budget.

   **Verification:** hold connections with no bytes, partial headers, and partial bodies; verify timely cleanup and successful admission of a subsequent valid request.

The process separation, execution-time document checks, explicit read-only boundary, and distinction between SDK consumption, precedent research, reused computation, and original adapter code are appropriate.
