- Preserve the complete `InformationReport`, including member casing, identities, sources, raw values, units, exclusions, and false completeness flags. Findings and incomplete coverage are successful observations, not execution errors or automatic readiness passes.
- Revit stays net48. No Autodesk assemblies or net48 core in the modern process; no MCP SDK/modern packages in Revit. No Autodesk redistribution. No automatic fixture installation or silent global client configuration.
- Private contract v1: four-byte unsigned little-endian byte length, strict UTF-8 JSON, one request/response per connection. Request **64 KiB**, response **4 MiB**, checklist **4 MiB**; no truncation.
- Maximum **8 connections**, **4 queued + 1 executing**; total request budget **30 seconds** from external-server admission; connect **at most 2 seconds**. One non-resetting **5-second** first-frame timer starts at pipe acceptance. Subsequent work uses validated remaining deadline capped by accept time plus 30 seconds.
- Contexts: **32 live**, **5-minute** expiry, no silent eviction; bind bridge session, open-document lifetime, ProjectInformation UniqueId, canonical path, and checklist ID/path/SHA-256. Hash and parse the same bounded bytes. Recheck on the Revit API thread.
- Queries never start transactions or modify model data. Cancel queued work, discard late results, never interrupt/kill Revit. Model text is data, not instructions.
- Installation is explicit/per-user with Revit closed; preserve owned-file inventory, existing add-in/core identity, optional fixture core synchronization, and rollback. No unrelated client entries or model inputs may be overwritten.
- Acceptance A1–A9 remains required, including all three existing samples and NC1/NC2, both actual desktop clients, independent verification, and external implementation review. No source/build/probe result is labeled live Revit acceptance.

## Review Focus

1. Two copies share a project UniqueId, or a file is closed/reopened: token must reject the changed document lifetime/path (Tasks 4, 5, 7).
2. Cancellation/expiry during sidecar preparation or evaluation: carry the same lifetime to the actual read boundary, prevent a new read, discard late success, and retain resources until their last user finishes (Tasks 2–7).
3. Shutdown finds idle open stdin, partial pipe input or an in-flight reader: wake waiters without EOF, preserve deadlines, and distinguish caller completion from physical cleanup (Tasks 1–4, 7).
4. Zero findings accompany incomplete coverage: preserve exact unexamined identities and distinct false flags, and require truthful client presentation (Tasks 6, 8).
5. Installation stops after its first mutation, deletion, fixture update or during recovery: pre-mutation backups and repeatable recovery must restore prior owned state while preserving unrelated files (Task 7). Unicode framing/evidence checks remain in Tasks 2, 6 and 8.

**One budget per process, no resets.** Task 6 creates the external lifetime once at admission. Task 3 validates the original UTC deadline and constructs one monotonic receive budget bounded by accept+30 seconds. Clock values cannot be shared across processes; the original deadline and still-running external timer enforce the end-to-end cap. Frame time is already spent. Queue, executor, serialization and writes borrow the established budget; they never call Admit/Receive again.

**Logical finish and physical finish differ.** Task 2 defines RequestLifetime (owns cancellation state, transport signal, notification and deadline work), BridgeExecutionContext (borrowed immutable request/budget/cancellation view), and DispatchTicket (Response and Quiesced tasks). Task 4 settles Response at most once; Quiesced completes only when the callback can no longer touch Context. An endpoint can close/release a connection when canceled but retains the lifetime until Quiesced AND notification/deadline/origin work complete, then disposes it once and releases its retained-request permit. A terminal canceled/expired operation cannot become successful. Test simultaneous cancel/complete; hold no lock across a Revit read and never claim cancellation preempts an already-started API read.

**Recovery precedes mutation.** Task 7 uses `Preparing → Prepared → Applying → Committed` or `RecoveryRequired → Restoring → Restored`. Complete prepared records/backups, not success-only receipts or the last progress marker, determine recovery. Classify actual target bytes as before/after/absent to recover a mutation without its completion marker. A foreign state is a conflict, never permission to overwrite it. Durability addresses process interruption and ordinary I/O failure with flushed records; physical-media failure or hardware that ignores durability is not claimed.
