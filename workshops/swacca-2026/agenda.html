The handoff is a starting point

Use · learn · extend

What participants take away

  • The planned Revit readiness plugin and matching source, with installation and tested-version guidance.
  • A build story with actual prompts, research, decisions, corrections, and Git checkpoints.
  • Versioned resources, license observations, sample preparation, and independent expected results.
  • Agent instructions, lessons, and templates for adding a rule or starting another BIM tool.

What to show in the repo

  • README: choose a starting point and AGENTS.md: provide project context.
  • Git lesson and research sources and code inspection.
  • Build journal and three demo questions.
  • Extension workflow and reusable templates.

Suggested participant prompt

Read README.md and AGENTS.md. Explain how the readiness example works, guide me to the relevant lesson, and help me add one rule. Establish the expected result, show the changes, verify the behavior, and save a Git checkpoint. Tell me what remains untested.

Keep the structure, refine the evidence

Planning notes
  • Use the plugin built before the seminar, selected source changes, and prepared demonstrations. Detailed installation and full walkthroughs belong in the teaching repository.
  • Let research findings and real corrections supply the examples. Record them as they happen; link lessons to actual commits.
  • Keep Git near the start, make source inspection visible, and protect the second session’s repository handoff time. Preserve a five-minute question block in each hour.
  • Adjust depth to the room. A scripting comparison can support the build story when useful. The five-minute application exercise can use an office task or the Summit Challenge.
  • Revit 2024 is the first required target. State compatibility and quantity behavior only as far as the verification supports them.
  • Rebalance blocks as the build and rehearsal develop, while keeping each session at 60 minutes. Use this file as the current timing source.
