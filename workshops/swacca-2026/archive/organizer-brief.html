What attendees should do on Monday

The target workflow

The goal is a repeatable way to start, not a finished plugin. Back at their desk, an attendee should be able to:

  1. Think the idea through with an LLM and plan it before writing any code.
  2. Research what already exists (Dynamo graphs, pyRevit tools, open-source add-ins, vendor features) to reuse, adapt, or learn from.
  3. Gather the APIs and SDKs the idea needs, starting with the Revit API.
  4. Set up a repository for the project.
  5. Install and configure Claude Code or Codex.
  6. Write the project memory first (CLAUDE.md or AGENTS.md), so the agent keeps the rules and context between sessions.

The reference tool

Built before the summit
WORKING NAME · WALL & CEILING MODEL INVENTORY

The week before the summit, we will build a small, read-only Revit tool with an AI agent and document every step. At the summit we walk through how it was built rather than live-coding it. Attendees take home the repo and the process guide.

What it does

  • Reads a model and reports wall types, layers, fire and STC ratings, heights, lengths, and net area after openings
  • Reports ceiling types and heights
  • Groups everything by level and exports to Excel or CSV
  • Lets an AI agent ask the model these questions directly through MCP (Model Context Protocol)

Why this tool

  • Remapping generic architect wall types by hand is the most-cited pain point in our research
  • Nothing free and current extracts trade-scoped quantities from Revit
  • Read-only, so it is safe to run on live projects
  • Runs on Revit 2022–2027. Autodesk's official Revit MCP server needs Revit 2027.2 or later, which most firms aren't on yet

The same tool appears at every level: L0 asks it questions, L1 sees it as a short pyRevit script, L2 extends the add-in, and L3 adds a new MCP tool.

This builds on what SWACCA members said at the 2025 summit, where custom plug-in development was a session topic and the first takeaway was:

"Having software development skills in-house can be a major differentiator."

  • Setup guide for Claude Code and Codex

Questions for you

Your input shapes the plan
  1. The Challenge. Would you welcome a Session 2 that helps teams apply AI tools to their Challenge problem? Does the 9:45 kickoff still fall between our two sessions?
  2. The room. Roughly how many attendees, and in what roles? Can we send a two-question pre-survey about Revit version and scripting experience?
  3. Revit versions. Do you know which versions member firms run? We're assuming about three years behind current.
  4. Laptops. Will attendees have laptops, and Revit, during the sessions or the build time?
  5. Overlap. Who gives the keynote, Education Session 3, and the vendor demos? We'd like to complement them, not repeat them.
  6. Distribution. How should the takeaway package reach attendees: a public repo, the member portal, a USB drive, or email after the event?
  7. Room setup. Projector, internet access for live demos, and whether we can run Revit on stage.
