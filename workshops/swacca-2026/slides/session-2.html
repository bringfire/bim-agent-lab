What MCP adds

MCP (Model Context Protocol) lets an AI application discover and call tools.

The shared evaluator applies the written rules. These calls read the model; they do not edit it or export files.

Two clicks, two tool calls. First the app asks for a fresh context: the add-in notes which model is open and which checklist applies, and returns a token. Then the app asks for the check with that token.

Two tools only, both read-only. The same evaluator used by the manual Revit command applies the checklist. If the model changes between the calls, the old token is rejected; that comes up again under verification.

Prepare recovery before the first write

Installing the bridge replaces files on a working machine.

Three clicks after the first box: install, undo twice, reinstall. A list of the files you intend to install cannot restore the files you already overwrote. Backups have to exist and be verified before the first replacement.

Keep the claim inside its scope

What the tool checksWhether required information is present. It does not validate a fire-rated assembly, certify compliance or establish whole-project readiness. Other host elements and links are outside this teaching scope.
Stale answers are rejected

An expired-token test alone does not prove model-switch detection. Switching models and recovering with a fresh context were tested live in both desktop apps.

Optional: if you are running long, skip this slide; the story holds without it. Three clicks after the first box. Handout page 5. A context token binds each request to the observed document and checklist, so an agent cannot report results about a model that is no longer the one open.

Keep the claim's boundary in view too: the tool checks presence of required information, nothing more.

Brainstorm before the spec: Superpowers

Superpowers is an open-source set of skills for coding agents (github.com/obra/superpowers, MIT). Its brainstorming skill asks what you are really trying to do, compares approaches, and writes a spec you review before any plan or code.

Available for Claude Code, the Codex app and other agents. We used version 6.4.2 on October 20; the current release is newer, so ask your agent which version it has.

Three clicks: brainstorm to spec, the plan behind its gate, then implementation and its review. The gates are the point: in the skill version we used, you approve the written spec before a plan is written, then review the written plan and choose how it is executed. You chose Native execution after the plan review.

Our first spec review found two major issues and one minor; the plan review found three major and one minor. The agent also used Superpowers' receiving-code-review skill to check each finding against the source before editing. The next slide is what to do when several major findings arrive at once.

For participants: in Claude Code the plugin installs with /plugin install superpowers@claude-plugins-official (as listed on the project page on October 28). The repository's agent procedure records the exact skill version and file used.

Ask what connects the findings

Two or three major findings are a signal.Ask whether they share a missing concept. The count is a cue to investigate, not proof.

Four clicks. The three findings are the real major gaps from the plan review (R2): cancellation could be lost before a Revit read, stopping the server could leave it waiting, and an interrupted install might lack backups.

You don't need to diagnose the technical issue yourself. Ask the reviewer to look across the findings, then hand that explanation to the coder along with the original findings. The next slide has the actual wording.

What that revealed in our build

The plan review found three major gaps: cancellation lost before a Revit read, a server that could hang while stopping, and an interrupted install without backups.

Two clicks: the message, then what to do with it. In plain terms: stopping your wait does not necessarily stop the Revit read. The read still needs its resources until it finishes, and its late result must not be presented as current.

Later cancellation findings showed a related gap: the coder had reasoned about who owned objects, but not fully about which work waited for other work. Tests then interrupted real operations at their handoffs.

One base, extended tool by tool

No forced upgrade.Autodesk's own Revit MCP server is a preview that needs Revit 2027.2. This base serves the years firms run today, and can sit alongside Autodesk's server on 2027.

Five clicks: the Revit years with stage 1, the model-reading stages, file checks, exports and changes, then the 2027 note. Everything after stage 0 is a plan, not support; the roadmap is docs/explanation/mcp-extension-roadmap.md.
