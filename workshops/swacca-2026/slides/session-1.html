Bring the BIM judgment.

You do not need to become a software developer to direct useful work. You do need to:

1

Explain the problem

Purpose, scope and the decision the answer supports.
2

Define a trustworthy answer

Known cases and a result you can check without trusting the agent.
3

Ask for evidence

What was observed, what was assumed, and what remains untested.

This is the thesis of both hours (handout page 1). The agent handles a lot of mechanical work. The BIM professional owns the meaning: what counts as useful, which requirements apply, and whether the result supports the work.

Make the work reviewable

A local commit is not a pushSaving a checkpoint and publishing it are separate decisions. Say which one you want.

Reusable wording, not a transcript. Note what it keeps out of Git: credentials, research clones and working Revit models. Our repository ignores .rvt files and the research clone folder.

Ask it to look first.

APIThe interface a program exposes, such as the Revit API.
SDKDevelopment tools and libraries for building against it.
DependencyAnother package our code needs to build or run.
RepositoryFiles plus their tracked history; a precedent or a starting point.

The author went on: SDKs, APIs, required libraries, dependencies, and GitHub repositories that might serve as precedents, "or as starting points if they have the proper license structure."

Participants don't need every package name in advance. They need to ask what role each resource plays.

Research and collect

Our agent investigated official Revit resources, local software and samples, and seven source repositories, cloned at recorded commits.

The agent recorded exact versions, relevant code, dependencies and license evidence. The research did not commit us to installing every tool or copying a particular bridge.

Reading the source changed the plan

Research findingWhat it meant for our work
An existing query looked only at the current view and defaulted to a 100-element limitA readiness report must say what it examined and whether anything was omitted
Revit API libraries and sample projects were already installedResource gathering could start with what was on the workstation
Candidate tools brought different packages, runtimes and license termsA promising repository still needed compatibility and reuse assessment
Some repositories had source components that were not downloadedGetting the main repository did not prove it was ready to build

A partial inventory cannot silently represent a whole model. A project description alone did not reveal that limit; inspecting the code did.

This is why we ask the agent to clone and read code, not just summarize a README. The 100-element default would have produced confident but incomplete answers.

That finding shaped the whole design: our results report requested versus examined counts and two completeness flags.

Consume, adapt, or learn from

Ask the agent to say which, for every resource it brings in.

Consume

A dependency

ClosedXML for the Excel report. The official C# MCP SDK 2.2.0 for the agent connection.
Adapt

Code with attribution

One small input-cancellation helper from the C# SDK's source, with attribution and its license kept.
Learn from

A precedent

The TypeScript MCP SDK 1.26.0 and existing Revit bridges. Studied; no code copied or installed.

License labels are evidence to review, not a blanket conclusion that everything may be redistributed.

These three categories carry different obligations. A dependency ships with your tool and brings its own dependencies. Adapted code needs attribution and license terms kept. A precedent costs nothing to ship but still needs to be checked.

The repository's THIRD_PARTY_NOTICES file records what we consume and adapt.

Make the division of work explicit

YouSupply professional intent, choose acceptable behavior and judge whether the answer is useful. In live demos, you operate Revit menus and permission prompts.
The agentResearches, inspects source, proposes a plan, writes code, runs checks and records evidence. Ask it to separate what it observed from what it assumes.
A useful follow-up“Show me the source or test that supports that claim. What remains unverified? What small check would resolve it?”

Ask for one Revit action at a time, with an exact file path. A similarly named model is not proof that the intended document is active.

Start with the smallest proof

The author didn't specify compiler flags, project files or installer scripts. The agent chose those.

A bounded outcome: inspect the real machine, fill genuine gaps, make one small read-only command work, and leave a record someone else can follow.

Agents start each session without memory. AGENTS.md (or CLAUDE.md) gives every session the same rules:

  • Purpose, audience and scope
  • Where each kind of work belongs
  • How to work: research, verify, commit
  • Commands and boundaries: what not to touch

Here, CLAUDE.md simply points to AGENTS.md, so Claude Code and Codex read the same instructions.

Long-term memory is part of the Monday-morning workflow: write it before the first build, and update it as decisions are made.

Our AGENTS.md also carries current status and safety boundaries, such as "no installer while Revit is open". It grew with the project.

Quick route: Dynamo

The agent writes the script; you run it in the correct Revit environment.

  1. Open a disposable sample project. Manage › Visual Programming › Dynamo; create a new graph.
  2. Set run mode to Manual. Place a Python Script node, select CPython3 and open its editor.
  3. Paste the two lines. Connect OUT to a Watch node and click Run.
import sys
OUT = ["Dynamo is working", sys.version]

Dynamo is included with Revit 2024, and its CPython3 engine has its own Python runtime. Next, ask for a read-only wall/ceiling inventory and compare its count with a native schedule.

Handout page 4. This only reports the Python version: a smoke check that the environment runs. It is not a rehearsed inventory script.

Ask the agent to confirm your installed Revit, Dynamo and engine versions first.

Quick route: pyRevit

A separate, optional add-in that runs Python scripts as ribbon buttons.

  1. Ask the agent to inspect the installed pyRevit version and Python engine, then create a small extension with a read-only script.py command.
  2. Have it give the exact registration and reload steps for that version. Run the button on the same sample and verify the output.

Dynamo and pyRevit use different host objects and may use different Python engines. Don't assume one script works in both.

pyRevit is not a prerequisite for following the seminar. These quick routes come before the compiled-plugin build: try one small read first.
