# MCP readiness server

This net10.0 Windows executable consumes official `ModelContextProtocol` **2.2.0**. It exposes exactly `revit_get_readiness_context` and `revit_check_required_type_information`, using the existing local bridge runtime. It never loads Autodesk or net48 readiness assemblies. Context acquisition has no arguments; checking requires the returned contextToken. Reports preserve original data and completeness flags; failures contain code/message/requestId/retryable without a report.

Run the built executable with optional `--revit-pid <positive-int>` and `--wire-evidence <new-directory>`. Discovery succeeds without Revit; selection is lazy and one bridge session is bound for this process. Restart the MCP server explicitly after replacing that session. No synthetic backend or participant protocol selector exists in production. Do not deploy with the old installer: Task 7 must add transactional installation/recovery first.

The SDK supplies protocol parsing/dispatch and default compatible negotiation. The separate [probe](../../tests/mcp-probe/Program.cs) and tool tests retain strict July regression. The existing stdin adaptation is attributed to C# SDK 2.2.0; the original host/trace/tool composition consumes it. TypeScript SDK 1.26.0 remains precedent-only. No new external package was added in Task 6; lock changes are lab project references only. See [dependency research](../../../../docs/research/mcp-sdk-dependencies.md) and [notices](../../third-party/mcp/README.md).
