# Verification strategy

The probe has a [manual Revit acceptance procedure](read-only-probe.md) and an [observed verification record](../docs/verification/2026-10-20-read-only-probe.md). The first readiness check adds 18 executable rule/aggregation tests, a [host acceptance procedure](required-information.md), a separate [fixture editor](fixture-tools/PrepareInformationFixture.cs), and an [independent schedule comparator](verify_information_evidence.py). See its [dated record](../docs/verification/2026-10-20-required-information.md) for observed results. No CI exists yet. Task 1 now adds [MCP protocol/stream/settings tests](../../../docs/how-to/verify-desktop-mcp-compatibility.md) through `../scripts/Test-McpBridge.ps1`; Task 2 adds [bridge foundation tests](../../../docs/how-to/build-and-verify-bridge-foundations.md) through `-Suite Framing` (33 per target, bilateral exchange and independent Python comparison); `-Suite All` runs both suites. See [corrected Task 2 evidence](../docs/verification/2026-10-21-bridge-foundations-review.md). Real pipes and Revit integration remain future work. [Original CP0 evidence](../docs/verification/mcp-client-compatibility.md) preserves the strict failures. [Amended CP0](../docs/verification/2026-10-20-desktop-mcp-compatibility.md) now passes in both actual desktops, with 19 C# tests, ten Python test methods, three compatible revisions and strict July regression retained.

From the project folder, run `& .\scripts\Test-Readiness.ps1`. This builds and runs 18 core tests, seven Excel workbook tests, and a host-like process-isolation test; it needs framework targeting/runtime support but no running Revit instance or third-party test library. It does not use `dotnet test`. The [Excel verifier](verify_excel_evidence.py) independently compares XLSX XML with saved reports and native schedule evidence; see the [Excel acceptance record](../docs/verification/2026-10-20-excel-output.md).

| Level | What it establishes | Requires Revit? |
|---|---|---|
| Rule and aggregation tests | Missing versus not-required values; type/instance effects; valid exceptions; counts and units | No, using controlled normalized inputs |
| Interface/contract tests | Request scope, result structure, completeness, errors, timeouts, and repeated requests | Some can use a test double; real bridge behavior requires Revit |
| Host integration | Correct API values, valid dispatch, document selection, and unchanged model after queries | Yes |
| Independent acceptance | Agreement with known fixture cases, manual inspection, and matching schedules | Yes |

The [information-check contract](../docs/required-type-information.md) is this increment's acceptance target. The [larger demo brief](../docs/demo-questions-and-sample-model.md) also includes physical conditions and quantities that remain planned. Test known defects and valid exceptions, and verify exclusions and partial results explicitly. Repeated type findings must not duplicate affected instance totals.

Record the host version, sample revision, build revision, scope, units, expected/observed results, and limitations using the [verification template](../../../templates/verification-record.md). Offline tests alone do not establish Revit compatibility.
